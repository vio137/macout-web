What is a MAC?
What is macchanger?

MAC: an address on the local link

MAC means Media Access Control. Ethernet and Wi-Fi commonly use a 48-bit address: six bytes, written as six hexadecimal pairs such as 02:7A:4C:91:B6:2E. A frame contains source and destination link-layer addresses. Switches use these addresses to forward frames on their local network.

An IP address belongs to the network layer. A router forwards an IP packet onto another link, with new link-layer framing. Your computer's source MAC is not carried as the source MAC through every router on the internet.

Permanent is not the same as current

The permanent address is the factory identity exposed by a driver, when available. The current address is what the interface uses now. Software can request a different current address without rewriting the hardware.

The lowest bit of the first byte selects individual (0) or group (1). The next bit selects universal (0) or local (1) administration. 02 is a simple locally administered unicast example. A copied vendor prefix is not proof of a device's maker.

macchanger: the Linux command-line tool

GNU macchanger displays and changes an interface's MAC address. -r requests a random address, -m sets an explicit address, -p restores the permanent address and -s displays address information. Root permission and driver support are normally needed for changes.

macchanger does the change. It does not provide MAC-OUT's profiles, rotation scheduling, before/after observations or export workflow.

MAC-OUT: the experiment around the tool

A Python + GTK 3 desktop application that wraps macchanger. Choose an interface and strategy, inspect the request, apply it, read the actual state and keep the result. Slow operations run away from the GUI thread.

Its advantages are context and repeatability: reusable profiles, address validation, a recovery attempt on explicit-target mismatch, local network checks and a redacted report. It does not guarantee anonymity, access or successful hardware support.

COMMAND TRACE / READ, DO NOT BLINDLY PASTE

One change,
step by step.

Illustrated with wlan0 and 02:7a:4c:91:b6:2e. Your interface may have a different name. The app uses argument lists, not a shell; paths depend on installed tools.

01 · Validate & snapshot

ip -j addr show dev wlan0
ip -j route show default dev wlan0
macchanger -s wlan0

Validate interface and address, remember the original, read /sys/class/net/wlan0/address and record the pre-change state. The permanent-address lookup uses macchanger output when available.

02 · Apply & restore link state

ip link set dev wlan0 down
macchanger -m 02:7a:4c:91:b6:2e wlan0
ip link set dev wlan0 up

The down/up calls happen only if the interface was up. The up call is attempted in a finally block even if macchanger fails. If it started down, it stays down. Random uses -r; permanent restore uses -p.

03 · Read back & compare

read /sys/class/net/wlan0/address
observed == explicit_target ?

This is Python file reading and comparison, not a shell command. An explicit target must match. Random mode has no preselected target to compare; it records the observed address. Failure may trigger an attempt to reapply the old address. Recovery can fail too.

04 · Recover the connection

nmcli device reapply wlan0
# if unsuccessful, try reconnect
nmcli device reconnect wlan0
# then available alternatives:
networkctl renew wlan0
# or dhclient -r wlan0; dhclient wlan0

Conditional fallbacks, not commands always run together. Renewal is requested when the prior state had a dynamic IPv4 lease or connected NetworkManager state. The app waits for link/address recovery and reports a timeout separately.

05 · Observe, then record

ping -c 1 -W 2 GATEWAY
Python getaddrinfo("example.com", 443)
TCP connect: 1.1.1.1:443
TCP connect: [2606:4700:4700::1111]:443

Gateway ping, DNS resolution and IPv4/IPv6 TCP reachability are distinct checks. An applied MAC can coexist with degraded connectivity. Save the result, duration and before/after snapshot, not a promise of anonymity.

06 · Optional persistence

nmcli connection modify CONNECTION \
  802-11-wireless.cloned-mac-address TARGET
# Ethernet uses 802-3-ethernet instead
# boot-only fallback:
systemctl daemon-reload
systemctl enable macout-persist.service

NetworkManager stores one connection profile's cloned address. Otherwise the app writes a unit whose ExecStart runs macout --apply-persistent at boot. Removing persistence is separate from restoring the current address.

Changes can drop your connection. Use a local console and authorized equipment. The browser never executes these commands or scans your network.

04 / KNOW THE BOUNDARY

Change the address.
Not the laws of networking.

01 / PRIVACY

A MAC change is not anonymity.

It can reduce a stable local identifier. It does not hide account logins, cookies, device fingerprints or your public IP. A vendor prefix is a pattern, not proof of a device's maker.

02 / VISIBILITY

Local observations only.

MAC-OUT cannot read your router's, ISP's or campus system's records. A green connectivity check says the test passed here, not that upstream tracking disappeared.

03 / RELIABILITY

The driver gets the final say.

Some drivers reject changes. Reconnects and DHCP may be disrupted. Persistence depends on the network stack: NetworkManager covers its connection profile; the fallback systemd unit applies at boot only.

04 / PERMISSION

Use a network you may test.

Use your own equipment or an authorized lab. Address collisions and access rules still matter. This is an observatory, not a promise of bypassing network controls.

05 / READY WHEN YOU ARE

Open source.
Local by design.

Python 3.8+, GTK 3 and macchanger. Ubuntu 22.04 x86_64 is the tested environment; other Linux desktops and ARM64 remain unverified.
